# 공정 순서 및 신호 연계

기준 코드: [project.mod](../project.mod). 신호의 상세 이름은 [원본 I/O 표](../DI_DO_Signals.csv)를 참고합니다.

| 단계 | 입력 신호 | 로봇 동작 |
|---|---|---|
| 투입 | `di21_1st_Con_End` | 컨베이어 1의 타이어를 프레스로 이송 |
| 프레스 후 냉각 | `di22_PressEnd` | 제품을 꺼내 냉각 자세 변경 후 컨베이어 2로 이송 |
| 색상 판별 | `di23_2nd_Con_End` | 색상 판별 위치로 이동하고 검정·흰색 신호에 따라 분기 |
| 정상 | `di04_plastic_black` | 컨베이어 3으로 이송 |
| 불량 | `di05_plastic_white` | 트래시 처리 분기로 진입. 반복 불량 처리에는 미구현 부분 있음 |
| 비드 코팅 | `di24_tool1_start` | 도구를 이용한 코팅 동작 |
| 원형 스프레이 | `di25_tool2_Start` | `MoveC`를 이용한 원형 동작 |
| 적재 | `di26_Store_Move` | `Count`에 따라 박스 1~4에 적재 후 일괄 이송 |

## 주요 루틴

- `Main`: TCP 연결과 명령 수신, 인터럽트 연결.
- `Run_Continuous_Production`: 첫 사이클 이후 `Count > 0`과 연결 상태에 따라 후속 사이클 진행.
- `Run_Production_Cycle`: 각 I/O 조건에 맞는 공정 동작 실행.
- `Reorient_CoolingSweep`: 냉각 위치에서 자세를 바꾸는 동작.
- `Grip_on`, `Grip_off`: 그리퍼 출력과 센서 응답 대기.
- `Trap_EStop`: 비상정지 입력에 대응하는 프로그램 트랩.

공정은 코드 안의 입력 조건을 검사하며 진행됩니다. 단일 상태 머신이 모든 입력 순서를 검증한다고 해석하면 안 됩니다. `Count`는 창고 박스 적재 상태이며 전체 누적 생산량이 아닙니다. 네 번째 박스까지 적재하면 일괄 이송하고 0으로 초기화합니다.

불량 처리 이후의 반복 동작과 센서 무응답은 [제한사항](limitations.md)을 확인해야 합니다.
